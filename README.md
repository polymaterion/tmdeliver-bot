# @tmdeliverbot — деплой на VPS

Telegram-бот попутчиков для маршрутов Россия ↔ Туркменистан. Этот README
описывает установку на "голый" VPS через Docker — с полной изоляцией от
других сервисов, которые будут на той же машине.

## Почему так устроено

- **Docker + docker-compose** — бот и его PostgreSQL живут в отдельных
  контейнерах со своей сетью. Другие сервисы на VPS не видят ни процессы
  бота, ни его базу данных, даже по `localhost` — порт БД никуда не
  пробрасывается.
- **Свой PostgreSQL-контейнер** — не используется общая база VPS. Когда на
  сервере появится второй сервис со своей БД, он получит свою отдельную
  сеть и контейнер точно так же, без каких-либо пересечений с этим ботом.
- **Ограничение ресурсов** — контейнерам бота и БД выставлен потолок по CPU
  и памяти, чтобы при сбое или наплыве пользователей они не забрали ресурсы
  у соседних сервисов на VPS.
- **Long polling, не webhook** — боту не нужен открытый порт наружу вообще,
  он сам стучится в Telegram, а не наоборот.

## 1. Первичная установка на чистый VPS

Все команды — по SSH на сервере, от пользователя с правами `sudo`
(например, ты уже зашёл как `root` или обычный пользователь с sudo).

### 1.1. Установить Docker и Docker Compose

```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER
```

После `usermod` нужно перезайти по SSH, чтобы группа `docker` применилась:

```bash
exit
```

Зайди на сервер заново и проверь, что всё встало:

```bash
docker --version
docker compose version
```

Обе команды должны вывести номер версии без ошибок `permission denied`.

### 1.2. Установить Git (если его ещё нет)

```bash
sudo apt update
sudo apt install -y git
```

### 1.3. Склонировать репозиторий

Клонируй именно по **HTTPS**, не по SSH — на многих VPS исходящий порт 22
(SSH) заблокирован хостером или файрволом, а порт 443 (HTTPS) почти всегда
открыт:

```bash
cd ~
git clone https://github.com/ИМЯ_ПОЛЬЗОВАТЕЛЯ/НАЗВАНИЕ_РЕПО.git tmdeliverbot
cd tmdeliverbot
```

Если репозиторий приватный, GitHub попросит логин и пароль — вместо пароля
нужен [Personal Access Token](https://github.com/settings/tokens) (обычный
пароль от аккаунта GitHub для клонирования больше не принимается).

Дальше все команды выполняются из этой папки (`~/tmdeliverbot`).

### 1.4. Настроить переменные окружения

```bash
cp .env.example .env
nano .env
```

Заполни поля в открывшемся редакторе:

| Переменная | Что вписать |
|---|---|
| `BOT_TOKEN` | Токен от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | Твой Telegram user_id (узнать у [@userinfobot](https://t.me/userinfobot)), через запятую если админов несколько |
| `CHANNEL_ID` | ID канала для публикации объявлений, вида `-100XXXXXXXXXX` |
| `BOT_URL` | `https://t.me/имя_бота` (можно оставить пустым — соберётся сам) |
| `HELP_USERNAME` | Username для кнопки поддержки, без `@` |
| `TZ_OFFSET` | `3` для московского/ашхабадского времени |
| `POSTGRES_PASSWORD` | Придумай длинный пароль (см. команду ниже) |

Сгенерировать надёжный пароль для `POSTGRES_PASSWORD`:

```bash
openssl rand -base64 24
```

Скопируй результат в `.env` вручную. `DATABASE_URL` заполнять не нужно —
она собирается автоматически внутри `docker-compose.yml` из
`POSTGRES_PASSWORD`.

Сохрани файл: `Ctrl+O`, `Enter`, `Ctrl+X` (если редактор — `nano`).

### 1.5. Запустить бота

```bash
docker compose up -d --build
```

Эта команда:
1. Соберёт образ бота из `Dockerfile`.
2. Поднимет контейнер `tmdeliverbot_db` (PostgreSQL) и дождётся его
   готовности (healthcheck).
3. Поднимет контейнер `tmdeliverbot_bot`, который при первом старте сам
   создаст все таблицы в базе.
4. `-d` — в фоне, `--build` — гарантированно собрать образ заново.

### 1.6. Проверить, что всё работает

```bash
docker compose ps
```

Оба сервиса (`tmdeliverbot_bot`, `tmdeliverbot_db`) должны быть в статусе
`Up` (у `db` — `Up (healthy)`).

```bash
docker compose logs -f bot
```

В логах должна появиться строка вида `Bot started as @имя_бота`. Останови
просмотр логов сочетанием `Ctrl+C` — это не остановит сам бот, только
отключит вывод логов в терминал.

Дальше напиши боту `/start` в Telegram и убедись, что он отвечает.

## 2. Обновление бота после изменений в коде

Это основной сценарий, с которым ты будешь сталкиваться регулярно. Все
команды — из папки `~/tmdeliverbot` на VPS.

### Шаг 1. Зайти на сервер и перейти в папку проекта

```bash
cd ~/tmdeliverbot
```

### Шаг 2. Забрать новый код из Git

```bash
git pull
```

Если команда зависает или падает с ошибкой подключения — скорее всего,
репозиторий был склонирован по SSH-адресу, а порт SSH (22) на этом VPS
заблокирован. Проверить, какой адрес используется:

```bash
git remote -v
```

Если видишь `git@github.com:...` — переключи на HTTPS и повтори `git pull`:

```bash
git remote set-url origin https://github.com/ИМЯ_ПОЛЬЗОВАТЕЛЯ/НАЗВАНИЕ_РЕПО.git
git pull
```

Если ты обычно редактируешь код здесь, в чате с Claude, и получаешь готовые
файлы — сначала закоммить и запушь их в свой репозиторий (с локального
компьютера или прямо отсюда, если у тебя настроен доступ), а уже потом
делай `git pull` на VPS.

### Шаг 3. Пересобрать образ и перезапустить бота

```bash
docker compose up -d --build
```

Что происходит:
- Docker увидит, что `main.py`/`locales.py`/`emojis.py`/`requirements.txt`
  изменились, пересоберёт только нужные слои образа (слой с зависимостями
  из `requirements.txt` пересоберётся, только если сам этот файл менялся —
  иначе переиспользуется кэш, и обновление проходит за секунды).
- Старый контейнер `tmdeliverbot_bot` остановится, новый — запустится.
- Контейнер `tmdeliverbot_db` и все данные в нём **не тронутся** — база
  живёт в отдельном volume независимо от пересборки бота.

### Шаг 4. Проверить, что бот поднялся без ошибок

```bash
docker compose ps
docker compose logs -f bot
```

Убедись, что видишь `Bot started as @имя_бота` и нет цепочки ошибок
(`Traceback`). `Ctrl+C` — выйти из просмотра логов.

### Если что-то пошло не так — откат

Откатиться к предыдущей версии кода:

```bash
git log --oneline -5        # посмотреть последние коммиты
git reset --hard <hash>     # вернуться к нужному коммиту
docker compose up -d --build
```

## 3. Полезные команды на каждый день

| Задача | Команда |
|---|---|
| Посмотреть живые логи бота | `docker compose logs -f bot` |
| Посмотреть последние 100 строк логов | `docker compose logs --tail 100 bot` |
| Перезапустить бота без пересборки (например, после правки `.env`) | `docker compose restart bot` |
| Остановить всё | `docker compose down` |
| Остановить и запустить заново | `docker compose down && docker compose up -d` |
| Статус контейнеров | `docker compose ps` |
| Зайти внутрь контейнера бота (для отладки) | `docker compose exec bot bash` |
| Зайти в PostgreSQL консоль | `docker compose exec db psql -U tmdeliverbot -d tmdeliverbot` |
| Посмотреть использование ресурсов | `docker compose stats` |

## 4. Резервное копирование базы данных

Рекомендуется настроить это сразу после первого запуска, не откладывая.

### Разовый бэкап

```bash
docker compose exec db pg_dump -U tmdeliverbot tmdeliverbot > backup_$(date +%Y%m%d_%H%M%S).sql
```

Файл `backup_ГГГГММДД_ЧЧММСС.sql` появится в текущей папке (`~/tmdeliverbot`)
на самом VPS — скачай его к себе на компьютер отдельно, чтобы не хранить
единственную копию бэкапа на том же сервере:

```bash
# Выполнять с ТВОЕГО компьютера, не на VPS:
scp пользователь@адрес_vps:~/tmdeliverbot/backup_*.sql ./
```

### Восстановление из бэкапа

```bash
cat backup_ГГГГММДД_ЧЧММСС.sql | docker compose exec -T db psql -U tmdeliverbot -d tmdeliverbot
```

### Автоматический ежедневный бэкап через cron

```bash
crontab -e
```

Добавь строку (бэкап каждый день в 4:00 утра по времени сервера):

```
0 4 * * * cd ~/tmdeliverbot && docker compose exec -T db pg_dump -U tmdeliverbot tmdeliverbot > ~/tmdeliverbot-backups/backup_$(date +\%Y\%m\%d).sql
```

Перед этим создай папку под бэкапы:

```bash
mkdir -p ~/tmdeliverbot-backups
```

## 5. Структура проекта

```
main.py              — код бота
locales.py            — тексты интерфейса на RU/TK
emojis.py              — реестр эмодзи
requirements.txt       — Python-зависимости
Dockerfile              — сборка образа бота
docker-compose.yml      — оркестрация бота + PostgreSQL
.env.example            — шаблон переменных окружения (копируется в .env)
.env                     — реальные секреты (НЕ в Git, создаётся вручную)
.dockerignore            — что не попадает в Docker-образ
.gitignore                — что не попадает в Git
Procfile                  — используется только при деплое на Railway,
                             для VPS-варианта не задействован
```

## 6. Если на VPS появится второй сервис

Просто клонируй его в отдельную папку (например `~/second-service`) со
своим собственным `docker-compose.yml` — если он тоже использует
`name: <имя>` и `networks:` с собственным именем сети, никаких конфликтов
с этим ботом не будет: разные имена проектов, разные сети, разные volume,
никакие порты БД никуда не пробрасываются.

Единственное, за чем стоит следить на VPS с несколькими сервисами —
суммарные лимиты `deploy.resources.limits` всех сервисов не должны
превышать реальные ресурсы сервера.
